# FidoParole Reader

An unofficial Android community companion by [Ordanexa](https://github.com/ordanexa). It reads existing FidoParole vaults over USB-C and lets you show or copy passwords. Use [Token2 FidoParole Desktop](https://github.com/token2/fidoparole) to manage and back up vaults.

## Current test build

[Download FidoParole Reader 0.1.6-test](apks/fidoparole-android-reader-0.1.6-test.apk?raw=true) · [SHA-256 checksums](apks/SHA256SUMS) · [APK archive](apks/)

Version **0.1.6-test** (2026-11-19) adds the Token2 serial-number query to the compact login. With a matching saved PIN and strong biometrics available, opening the reader or connecting a key while it is open starts biometric authentication automatically. Choose **Use PIN** in the prompt to enter the token PIN manually. Cancelling or failing biometric authentication also shows the PIN form without automatically retrying.

After authentication, touch the Token2 when it blinks. The fingerprint prompt and unlock status both describe this step. The connection button appears only while USB access is needed. **PIN options → Forget saved PIN** removes this app's stored PIN.

On first setup, enter the token PIN and optionally select **Save PIN for fingerprint unlock**. The encrypted PIN is saved only after the vault opens successfully. Saving for another token replaces the current saved PIN. Each app stores its own encrypted PIN independently.

The reader identifies the key before offering a saved PIN. It uses the Android USB serial number when available, otherwise the read-only Token2 serial-number command over HID feature reports. The old same-key confirmation dialog is removed. If neither method succeeds, manual PIN login remains available and saving or using a PIN for biometric unlock is disabled for that connection. A rejected saved PIN is never retried automatically.

After updating from a build that saved a PIN under `no-usb-serial`, enter the PIN once and select **Replace saved PIN on this device** to bind it to the detected serial number. The app retains the old encrypted record until a successful unlock saves the replacement. One saved PIN is stored per app. Saving a different key replaces that record.

The serial query uses the fixed read command implemented in [Token2's reference client](https://github.com/token2/token2-otp-cli/blob/c12197949271600f5576ce90ce5190fe2a84e7f5/token2/__init__.py) and [protocol reference](https://github.com/token2/token2-otp-cli/blob/c12197949271600f5576ce90ce5190fe2a84e7f5/docs/Token2-OTP-SDK-Protocol.md#610-read-serial-number). It runs in the background with bounded USB timeouts, consumes no PIN attempts and releases the interface before biometric or manual vault unlock. A serial number is a device identifier, not cryptographic attestation of the device.

- Android 13+ (API 33), USB-C, Token2 USB device `349e:0024`.
- Package `com.ordanexa.fidoreader`, version code 7. The archived build uses the existing signing identity for in-place updates.
- No vault or master password is persisted to disk. Only an opt-in encrypted token PIN is saved locally. Android backup is disabled.
- Uses Android biometric permission. No Internet, storage, NFC or accessibility permission.
- Android build, serial framing/parsing tests, all 154 existing protocol checks, APK alignment and the preserved signing certificate passed in [GitHub Actions](https://github.com/ordanexa/fidoparole-android-reader/actions/runs/44602305117).
- On-device testing of the serial query and 0.1.6-test is pending. Pascal confirmed fingerprint unlock followed by token touch in 0.1.4-test on the tablet.

## USB access with multiple apps

Open the app you want to use. The reader discovers the connected key and asks Android for USB permission when required. It does not register a USB attachment launch filter, so it is absent from Android's attachment app chooser.

The chooser shown when inserting a key is generated by installed apps that register USB attachment filters. KeePassDX-FIDO2 **0.1.7-test and later** includes a no-display attachment handler that finishes immediately without opening the database picker or claiming the token. Select **KeePassDX FIDO2 → Always** in Android's USB app chooser to use this quiet default, then open whichever app you want. The installed KeePassDX build must include this handler. [Handler source](https://github.com/ordanexa/KeePassDX-FIDO2/blob/b0588a701980ca705a1337cc775c5052c36c1c14/app/src/fido2/java/com/kunzisoft/keepass/fido2/UsbAttachActivity.java)

The reader's own manifest cannot change handlers or defaults registered by other installed apps.

USB permission is granted separately to each app. Explicit permission lasts until unplugging. Each app must release the FIDO interface before another app uses it. The reader releases USB access after reading and on backgrounding or unplugging. [Android USB host guide](https://developer.android.com/develop/connectivity/usb/host) · [USB permissions](https://developer.android.com/reference/android/hardware/usb/UsbManager#requestPermission(android.hardware.usb.UsbDevice,%20android.app.PendingIntent)) · [Exclusive interface access](https://developer.android.com/reference/android/hardware/usb/UsbDeviceConnection#claimInterface(android.hardware.usb.UsbInterface,%20boolean))

## Fixed feature scope

1. Connect the key over USB and grant Android USB permission.
2. Authenticate with the automatic fingerprint prompt, or choose **Use PIN**. Touch the key when it blinks.
3. Read existing vaults and entries.
4. Show/hide or copy a password. Passwords start hidden after every unlock.
5. Lock when the app enters the background, the key is unplugged, or the 60-second inactivity timer expires.

No create, edit, delete, reset, PIN change, backup import/export, NFC, sync or autofill.

**Read-only refers to vault contents and credentials.** Authentication can change internal authenticator counters and PIN retry state. An incorrect PIN consumes a real attempt. The app never retries a PIN automatically and stops when two or fewer attempts remain.

## Implementation

Native Java Activity and Android USB Host API; no WebView, Rust runtime or native libraries. Android/Java cryptographic providers supply P-256 ECDH, AES-CBC, HMAC/HKDF-SHA256 and AES-256-GCM.

- CTAPHID INIT/CBOR, fragmentation, keepalive and timeout handling.
- PIN/UV protocols 1 and 2; scoped GetAssertion permission where supported.
- Discoverable GetAssertion for `fido2-vault.token2`, `hmac-secret` and `largeBlobKey`.
- GetNextAssertion before any largeBlob reads.
- largeBlob checksum verification and AES-GCM/DEFLATE outer layer, followed by T2VLT v1 and JSON formats 1/2.
- Explicit CTAP allowlist blocks largeBlob SET and credential/PIN write operations.

Protocol identifiers, salts, key-derivation labels and stored vault data are compatibility requirements and are not translated.

## Build (Linux / WSL)

Requirements: JDK 21, Android command-line tools, `zip`; Python for tests only.

```bash
sdkmanager 'platforms;android-35' 'build-tools;35.0.0'
export ANDROID_HOME=/path/to/android-sdk
./build.sh
```

Output: `dist/fidoparole-android-reader-0.1.6-test.apk` and `dist/SHA256SUMS`.

By default, the build creates a local test key at `build/test-signing.jks`. See [APK signing](docs/SIGNING.md) for custom signing and update compatibility.

## Tests

The JVM tests use an **independent Python CTAP simulator** based on Yubico's `python-fido2` and Python `cryptography`. They check actual request/response bytes, HID fragmentation and decryption independently of the Java implementation. They do not replace Android USB tests.

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r tests/requirements.txt
./test.sh
```

See the [validation report](docs/VALIDATION.md), [device checklist](docs/DEVICE_TEST.md) and [reference notices](NOTICE.md).

## Limitations

- Clipboard content is marked sensitive. The app requests deletion of its own clip after 20 seconds and checks again on return. Android may restrict background execution or clipboard access, so **there is no guaranteed deletion deadline**. Other apps may retain pasted passwords.
- FLAG_SECURE protects screenshots and recent-app previews. It does not protect a compromised Android device.
- Byte/character arrays are cleared where possible. Java, Android, JSON and the clipboard also use immutable strings, so complete memory zeroization is not guaranteed.
- The USB transport closes after reading. Android's detach broadcast locks the displayed entries when the key is unplugged.
- The app does not log PINs, passwords or CTAP dumps.
